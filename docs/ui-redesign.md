# 迅搜 UI/UX 重构设计方案（v2）

> 对象：`xunsou` 1.0.0（egui 0.30 + eframe）
> 范围：仅界面与交互层。`model.rs` / `indexer.rs` / `search.rs` / `win.rs` 的索引与检索逻辑保持不变。
> 配套：高保真可交互原型见 `docs/ui-mockup.html`（双击打开即可，支持深浅主题、三档窗口宽度、分类筛选、表头排序、行选中与预览联动）。可用锚点直达状态：`#light` 浅色、`#w1024` 折叠侧栏、`#w760` 窄屏。

---

## 0. 结论先行

当前界面是「四个 Panel 拼起来的可用窗口」：68px 汉字图标栏 + 固定 5 列结果表 + 300px 预览 + 28px 状态栏，信息能显示，但**层级、可发现性、反馈、响应式四件事都没做**。这次重构的核心动作是把界面从「控件堆叠」改成「检索工作台」：

1. **信息架构三栏化**：左侧「值得筛选的维度」（分类 / 标记 / 索引范围，208px 可折叠到 56px），中间「结果」（唯一视觉重心），右侧「选中项」（可拖宽的检视面板）。三者职责互不重叠。
2. **视觉去噪**：唯一强调色（品牌蓝）+ 中性灰阶骨架，分类色与标记色全部退到「16px 图标着色 + 8% 浅底」的次要层级，取消彩虹色块；深/浅双主题，默认跟随系统。
3. **交互补齐**：完整键盘模型（↑↓ / Enter / Ctrl+Enter / Ctrl+C / Alt+1–7）、Shift 连选、行内悬浮操作、三态空态、Toast 反馈、索引进度条。
4. **响应式**：以 `available_width()` 为断点的五档布局（1180 / 980 / 820 / 680），最窄档取消侧栏并改为横向 chips，路径列下沉为行内副标题，保证 720px 宽仍可用。

改动集中在 `src/app.rs`（1441 行，拆为 `ui/` + `app/` 两组模块），新增约 6 个文件、约 1800 行；配置结构新增一个 `UiPrefs` 段（向后兼容，旧 `config.json` 可直接读）。

## 2. 设计目标与原则

**目标**：让「输入关键词 → 认出目标 → 打开/定位」这条主链在 3 秒内完成，且全程可以不用鼠标。

| 原则 | 落地做法 |
|---|---|
| 内容优先 | 结果表占 60% 以上面积；除品牌色外所有颜色只用于状态，不用于装饰 |
| 识别优于回忆 | 分类用「图标 + 文字 + 计数」，不用单字徽章；快捷键在控件内以 `kbd` 常驻提示 |
| 就近操作 | 高频动作（打开/定位/复制/标记）悬浮在行尾，不藏在右键菜单 |
| 即时反馈 | 任何改变状态的操作 ≤100ms 内有可见响应；耗时操作 >80ms 才显示进度，避免闪烁 |
| 渐进披露 | 侧栏可折叠、预览可关闭、设置在独立对话框；不把 7 个按钮平铺在顶栏 |
| 一致性 | 一套 4pt 间距网格、一套字号阶梯、一套圆角、一套图标线宽 |

## 3. 视觉系统

### 3.1 色彩

策略：**中性灰阶承担 90% 的表面与文字，品牌蓝只标记"当前/主行动"，语义色只表达状态**。分类色与标记色降为「小面积着色」，不再做大色块。

| 语义令牌 | Dark | Light | 用途 |
|---|---|---|---|
| `bg.base` | `#0F1115` | `#FFFFFF` | 窗口底 |
| `bg.surface` | `#16191F` | `#F7F8FA` | 侧栏、顶栏、状态栏 |
| `bg.hover` | `#1B1F26` | `#F1F3F6` | 行/按钮悬浮 |
| `bg.raised` | `#22272F` | `#FFFFFF` | 浮层、菜单、Toast |
| `border` | `#262B33` | `#E3E6EB` | 1px 分隔线 |
| `border.strong` | `#343B45` | `#CBD2DA` | 输入框、浮层描边 |
| `text.primary` | `#E7EAF0` | `#111827` | 文件名、标题 |
| `text.secondary` | `#9DA6B4` | `#4B5563` | 路径、元信息 |
| `text.tertiary` | `#7A8494` | `#6B7280` | 计数、时间戳（对比度 ≥4.5:1） |
| `brand` | `#3B9EFF` | `#0B6BCB` | 主按钮、选中条、焦点环 |
| `brand.soft` | `rgba(59,158,255,.12)` | `rgba(11,107,203,.08)` | 选中行底、激活项底 |
| `ok / warn / danger` | `#3DD68C` / `#F5A524` / `#FF6B6B` | `#17803D` / `#B45309` / `#C81E1E` | 就绪 / 索引中 / 错误 |

**分类色**统一到 Tailwind 500 级（同一亮度带，避免现在的 Material 混搭）：图片 `#10B981`、文档 `#3B82F6`、视频 `#F43F5E`、音频 `#A855F7`、手机 `#F59E0B`、目录 `#64748B`、全部 = `brand`。

**标记 8 色**：`#EF4444` `#F97316` `#F59E0B` `#22C55E` `#14B8A6` `#3B82F6` `#8B5CF6` `#64748B`。色相均匀分布、亮度一致，色点在深色底上仍可辨；不做红绿以外的纯色相区分依赖（红绿色盲用户可凭位置记忆）。

### 3.2 字体

| 用途 | 字族 | 字号/字重 | 行高 |
|---|---|---|---|
| 界面正文 | Microsoft YaHei UI → PingFang SC → Segoe UI | 13 / 400 | 20 |
| 表头、分区标题 | 同上 | 12 / 600，字距 +0.02em | 16 |
| 次要信息（路径、时间、计数） | 同上 | 12 / 400 | 16 |
| 极辅（kbd、版本号） | 同上 | 11 / 500 | 14 |
| 空态标题 | 同上 | 16 / 600 | 24 |
| 路径、大小、时间、文本预览 | Cascadia Mono → Consolas | 12 / 400 | 18 |

理由：现有代码 6 种半像素字号收敛为 5 档整数；数字列改等宽后大小/时间纵向自然对齐。

### 3.3 间距 / 圆角 / 描边 / 动效

- 间距：4pt 网格，取值 `2 / 4 / 8 / 12 / 16 / 24 / 32`。面板内边距 12，控件间距 8，分组间距 16。
- 圆角：控件 4（chip、kbd）、输入与按钮 6、浮层 8、色点/胶囊 999。
- 描边：统一 1px；仅焦点态叠加 2px `brand` 环（向外 1px 偏移），且只在键盘导航时出现。
- 阴影：主界面**全部取消**（现状也无阴影，保持一致）；仅浮层/Toast 使用 `0 8px 24px rgba(0,0,0,.32)`（dark）/ `0 6px 20px rgba(15,23,42,.12)`（light）。
- 动效：`120ms ease-out` 用于 hover/展开；`180ms` 用于面板滑入/Toast 进出。不做弹跳、不做渐变色动画。

### 3.4 图标

现状用汉字徽章规避 emoji 字体缺失，这是对的判断，但方向错了——1 个汉字的信息量远低于图形。

**推荐方案：自建 `src/ui/icons.rs`，用 `egui::Painter` 的 `circle/line/path` 绘制 16px 线性图标（stroke 1.5，`currentColor`）。**
理由：零新依赖、体积极小、可随主题着色、可在无头测试中断言、不受系统 emoji 字体影响。备选方案 `egui-phosphor`（字体图标，一行依赖即可，但会给 kittest 的无障碍树引入额外字形节点，且字重不可调）。

首批 16 个：`search` `folder` `image` `doc` `video` `audio` `phone` `tag` `settings` `refresh` `close` `chevron-down` `check` `copy` `external` `shield`（+ `sun/moon` 主题切换、`grid` 密度、`panel-right` 预览开关）。

统一接口：

```rust
pub fn icon(ui: &mut egui::Ui, kind: Icon, size: f32, color: Color32) -> egui::Response;
```

## 4. 信息架构与布局

### 4.1 整体结构（≥1180px）

```
┌──────────────────────────────────────────────────────────────────────┐
│ ◈ 迅搜   [🔍 搜索文件与文件夹…              ✕  Alt+`]   1,204 条·38ms ⋯ │ 64
├──────────┬───────────────────────────────────────────┬───────────────┤
│ 分类      │ ☐ 名称 ⇅        路径              大小 ⇅   修改时间 ⇅   │ 32 表头
│ 全部 1.28M│ ☐ 📄 report.pdf  D:\工作\2026\Q4\…   2.4 MB  今天 14:32   │
│ 图片 84.1K│ ☐ 🖼 sunset.jpg  C:\Users\…\Pictures  1.8 MB  昨天 09:12   │ 32 行
│ …         │                                            │  预览 320px   │
│ 标记      │                                            │  缩略图/文本   │
│ 索引范围  │                                            │  元信息 3 行   │
├──────────┴───────────────────────────────────────────┴───────────────┤
│ ● 就绪 · MFT 索引 · 1,284,331 项           上次索引 0.9s   v1.0.0     │ 26
└──────────────────────────────────────────────────────────────────────┘
```

尺寸：默认窗口 1180×760（现 1020×680），最小 720×480（现 760×480）。

### 4.2 顶栏（64px）

从左到右：品牌标记 24×24 → 搜索框 `flex:1`（高 38，圆角 6，左内嵌 14px `search` 图标）→ 结果元信息 `1,204 条 · 38 ms`（等宽 12）→ 图标按钮组（密度 / 预览开关 / 设置，各 28×28）。

搜索框内部：左侧放大镜、右侧 `✕` 清除（有内容时才出现）与 `kbd` 形式的当前热键提示（`Alt + \``，11px，`border` 描边）。聚焦时描边转 `brand` + 2px `brand.soft` 环；无内容时显示占位「搜索文件与文件夹，空格分隔多关键词」。

删除「打开位置 / 隐藏预览 / 设置」三个文字按钮：打开位置随选中项走（行内 + Enter），预览用图标开关，设置在侧栏底部常驻 + `Ctrl+,`。

### 4.3 左侧栏（208px / 折叠 56px）

三段，`12px` 内边距，段间 16px + 1px 分隔线：

1. **分类**：7 项，每项 32px 高，`图标16 + 文字 + 右对齐计数`（等宽 11，`text.tertiary`）。选中项：`brand.soft` 底 + 左侧 2px `brand` 竖条 + 文字转 `text.primary`；未选中文字 `text.secondary`。计数按 1 万进位缩写（`84.1K` / `1.28M`），悬浮显示精确值。
2. **标记**：一行 8 个色点（18px）+ 下方「已标记 N 项」和「清除全部」文字按钮。点击色点 = 只看该颜色标记，再点取消。
3. **索引范围**：卷列表（`disk` 图标 + `C:` + 容量/条目数），勾选控制是否参与检索；底部「排除目录…」入口打开设置对应分区。

栏底固定：主题切换（sun/moon）、设置（gear），各 28×28，右对齐。

折叠态（56px）：仅图标居中，文字藏进 tooltip；选中项保留左侧竖条 + `brand` 图标着色。

### 4.4 结果区

表头 32px（sticky）：`☐` 全选 | 名称 | 路径 | 大小 | 修改时间 | 标记。
列宽：`32 / minmax(220,2fr) / minmax(150,1.8fr) / 88 / 132 / 28`，可拖拽、写入 `UiPrefs.columns`。

行 32px（舒适 40 / 紧凑 28，可切换）：
- 悬浮：`bg.hover`，行尾浮出 4 个 24×24 操作图标（打开 `external` / 定位 `folder` / 复制 `copy` / 标记 `tag`），容器为 `bg.raised` + 1px 描边圆角 6，避免与文字打架。
- 选中：`brand.soft` 底 + 行首（表头左侧）2px `brand` 竖条；文件名 600 字重。
- 名称列：16px 分类图标（着色）+ 文件名（超长中间省略，`tooltip` 完整名）+ 目录名后置 `/`。
- 路径列：`text.secondary`，只显示父目录（文件名已在左列），hover 显示完整路径；双击 = 打开所在位置。
- 大小列：右对齐等宽；目录显示 `—`。
- 时间列：相对时间（今天 14:32 / 昨天 / 10月12日 / 2025/06/01），tooltip 给精确到秒的完整时间。
- 标记列：有标记时显示 8px 色点，无标记时 hover 出现淡描边圆点，点击直接开色板。

### 4.5 右栏预览（320px，可 260–480 拖拽）

- 头部 44px：16px 类型图标 + 文件名（省略）+ 关闭 `✕`。
- 内容区：
  - 图片：棋盘格底，等比贴合宽度，最大高度 `内容区 - 96`（不再用魔法数，改为布局计算）。
  - 文本：等宽 12/18，**只渲染可视行**（`ScrollArea::show_rows` + 行号栏），不再把 128KB 塞进 `TextEdit`。
  - 其他：居中大图标 + 「此类型暂无内置预览」+ 「打开」次要按钮。
- 元信息区（固定 3 行）：大小 / 修改时间 / 完整路径（两行截断 + 复制按钮）。
- 底部标记区：8 色点 20px + 「移除标记」。

### 4.6 状态栏（26px）

左：状态点（6px 圆，ok/warn/danger）+ 阶段文字 +（索引中）`120×3` 进度条 + `volumes_done/total` + 总条目数。
右：本次搜索耗时 + 结果数 / 上次索引耗时 / 版本号。
「以管理员重启」从平铺按钮改为状态栏左端的**可点击警示徽章**（`warn` 底 + `shield` 图标 + 「启用极速索引」），仅非管理员且非 MFT 模式时出现；点击弹出说明再执行，不再是一个大字按钮横在状态栏中间。

### 4.7 响应式断点

| 档位 | 宽度 | 侧栏 | 预览 | 表格变化 |
|---|---|---|---|---|
| XL | ≥1180 | 208 展开 | 320 常驻 | 全列 |
| L | 980–1179 | 208 展开 | 288 常驻 | 全列 |
| M | 820–979 | 56 图标态 | 264，默认开 | 路径列 `min 140` |
| S | 680–819 | 56 图标态 | 默认关，点按为右侧抽屉 300（覆盖层） | 隐藏「标记」列，色点并入名称前 |
| XS | <680 | 隐藏，改顶部横向 chips（可滚动） | 全屏覆盖层 | 路径下沉为名称下方第二行（行高 44），隐藏「大小/时间」列，元信息进 tooltip |

高度断点：`<560` 时状态栏只保留状态点 + 阶段 + 条目数，行高强制 28。

用 `ui.available_width()` 在每帧开头算一次 `Breakpoint`，各面板读同一个值——egui 没有媒体查询，这是最省事且不会抖动的做法。

## 5. 关键组件规格

| 组件 | 规格 |
|---|---|
| 主按钮 | 高 32，圆角 6，`brand` 填充，白字 13/600，hover 提亮 8%，按下压暗 6%，禁用 `border` 底 + `text.tertiary` |
| 次按钮 | 高 32，`bg.surface` 填充，1px `border`，`text.primary` 13/400，hover `bg.hover` |
| 图标按钮 | 28×28，`text.secondary`，hover `bg.hover` + `text.primary`，激活 `brand`，必有 tooltip |
| Chip（窄屏分类） | 高 26，圆角 999，13/500，未选 1px `border`；选中 `brand.soft` 底 + `brand` 文字 + `brand` 描边 |
| 输入框 | 高 32（搜索 38），圆角 6，1px `border.strong`，focus 2px `brand.soft` 环 |
| 复选框 | 16×16，圆角 3，选中 `brand` 底 + 白色 `check`；行内复选框默认 40% 不透明，hover/选中转 100%，减少表格噪点 |
| `kbd` | 高 16，圆角 4，1px `border`，11/500 `text.tertiary`，内边距 4×2 |

## 8. 风险与兼容性

1. **无头测试依赖无障碍文本**。`app.rs` 的 kittest 用 `get_by_label("设置")`、`by_label_contains("视频"/"文件大小"/"全部")` 定位（`app.rs:1319-1430`）。重构必须保留这些 label 文案与 `WidgetType::Button` 角色；汉字徽章改图标后，`c.label()` 仍要作为 `widget_info` 的 label 传入，否则 7 个测试全部失效。自绘控件一律保留 `resp.widget_info(...)`。
2. **像素快照会失配**。`tests/snapshots/main.png` 必然变化，需执行 `UPDATE_SNAPSHOTS=1 cargo test` 重生成基线；这属于验收动作，不在本次改动范围内。
3. **egui 0.30 API**：`Rounding`（非 0.31 的 `CornerRadius`）、`Frame::none()`、`Visuals::light()/dark()`；`apply_theme` 需在主题切换时重新调用（现只在首帧调用一次，`app.rs:507-512`）。
4. **性能**：表格已用 `TableBuilder::body` 虚拟化，改列宽/行高不增加成本；预览文本改 `show_rows` 后，128KB 文件不再一次性布局。新增的计数（分类/标记/卷）需缓存，每帧全量遍历 128 万条会掉帧——按 `index.epoch` 做一次惰性统计。
5. **配置兼容**：`UiPrefs` 全部带 `#[serde(default)]`，旧 `config.json` 缺字段时走默认值，`marks` 的 `BTreeMap<String,u8>` 结构不变。

## 附三：第二轮修正（路径语义与预览能力）

第一轮校对把「能看到」的问题修完了，但索引与预览的实际数据路径仍有硬伤。本轮以真实文件为样本重跑校对。

### 1. 路径列只显示盘符（根因）

**现象**：结果表「文件路径」整列只显示 `G:`，一万多个文件全都挂在卷根。

**根因**：遍历扫描（非 NTFS / 无管理员权限时走这条路径）把子目录入队时用的是**父目录**的下标：

```rust
// 修复前
g.q.push_back((sub, parent_idx));   // 应为子目录自己的 idx
batch.push(EntryRecord { ... parent_idx, name, .. });
```

每层都上跳一级，最终所有条目塌缩到卷根；`path_of` 沿父链只能拼出 `G:`。
由于子目录条目要等批次落盘才有下标，正确做法是**把目录与文件分开攒**：目录先单独落盘拿到 idx，再连同 idx 入队。

修复后新增回归用例 `indexer::walk_probe::walk_keeps_full_parent_chain`：在临时目录里造三层嵌套 + 两个文件，断言 `T://a//b//c//leaf.txt` 的完整路径成立。

### 2. 路径列被左截断，恰好切掉最有用的末级目录

`D://缓存//2026-09-26-01-13-...` 这类显示等于没显示——搜索场景里区分同名文件靠的正是最后几级。

改为**尾部优先压缩**：按实际像素宽度从后往前塞目录段，放不下就停，前缀用 `…\` 表示。列宽同步从 58:42 调到 50:50，路径字号 11.5 → 11、颜色 text3 → text2。鼠标停留可看完整路径。

### 3. 预览：从「只有文本」到图片 / 视频首帧

| 类型 | 实现 |
|---|---|
| 位图（png/jpg/gif/bmp/webp） | `image` crate 直接解码，超过 1600px 先缩略 |
| 文本（代码/配置/csv…） | 读前 128KB，含 NUL 则判定为二进制 |
| 视频首帧 | Windows `IShellItemImageFactory::GetImage` |
| PDF / Office / HEIC / RAW | 同上（系统缩略图处理器） |
| 目录 / 无处理器 | 明确空态，不回退成通用图标 |

视频没有自研解码器，走的是资源管理器同一条缩略图管线：`SHCreateItemFromParsingName` → `QueryInterface(IShellItemImageFactory)` → `GetImage(SIIGBF_THUMBNAILONLY)` → `GetDIBits` 转 RGBA。命中系统缩略图缓存时几乎零 IO，且一次覆盖所有已注册格式。手写 vtable 调用，未引入额外 crate。

链路验证：`thumb::probe` 对系统壁纸断言「有图、尺寸合理、颜色不单一、alpha 归一」，对不存在的文件断言安静返回 `None`。

### 4. 深色下月亮图标有一道斜穿线

月牙由两段圆弧拼成，端点没对齐，`Shape::closed_line` 会补一条弦。改为先求两圆交点、两段弧共用端点，再用 `closed_line` 闭合。

### 5. 设置对话框与背景粘在一起

- 加模态遮罩（浅色 55 alpha / 深色 120 alpha），同时吃掉背景点击
- 去掉系统标题栏（默认灰底与色板冲突），自绘 44px 标题行 + 关闭按钮
- 高度上限 560 → 640，「关于」不再被按钮区压住
- footer 加顶部分隔线

### 6. 视觉微调

- 分类色统一到 S≈55% / L≈48% 低饱和带：七种高饱和色在 16px 图标上会让整个侧栏和表格「发花」
- 顶栏搜索框吃掉剩余空间，计数与图标贴右成组，中间不留空洞
- 行悬停补一条 2px 弱左条，暗示整行可选

## 附四：第三轮修正（路径样式、应用图标、删除）

### 1. 路径列改回「盘符开头」

第二轮的尾部优先压缩（`…\父\子`）识别不了**属于哪个盘、哪个顶层目录**——用户给的参考样式
（Everything / WizTree 风格）是把路径从盘符开始整串显示：`G://game//DNF旧版解包//A3解包 Sc...`。

最终采用参考样式：路径单元格直接显示完整父路径、宽度不足截尾。要点是**开头恒为盘符**，
行首一眼可辨归属；被截掉的尾部由悬停提示补全。`fit_path` 的逐段测量随之删除——
不再需要每行多次排版测量，虚拟列表更省。窄屏两行式的第二行同步改为完整路径。

### 2. 应用图标

设计：品牌蓝圆角底 + 白色放大镜 + 镜片内闪电（呼应「迅搜」），与参考图的扁平风格一致，
4× 超采样抗锯齿，7 档尺寸（16–256）。

嵌入方式上本机没有 Windows SDK 的 `rc.exe`，`winresource`/`embed-resource` 都不可用。
最终链路：

1. `assets/make_res.py` 按 32 位 .RES 规范直接写出 `app.res`
2. MSVC 的 `cvtres.exe` 把 .res 转成 COFF 目标 `assets/app.obj`
3. `build.rs` 用 `cargo:rustc-link-arg-bins` 把 obj 接进链接

两个来之不易的教训：

- **.RES 里不能有首尾的空资源条目**——规范说文件以空条目开始结束，但 `cvtres.exe` 会直接判
  CVT1107「已损坏」。用 cvtres 做黑盒穷举（DataVersion × HeaderSize 语义 × MemoryFlags ×
  空条目 × pad 策略，96 组合）才定位到。
- **link.exe 的内置 .res 解析比独立 cvtres.exe 更挑剔**（LNK1136），同一个 .res
  cvtres 认、link 不认。所以最终交给链接器的是 cvtres 的产物 `.obj`，绕开整层解析。

窗口/任务栏图标走 `ViewportBuilder::with_icon`（32px PNG，`include_bytes!` 内嵌，失败时退回默认）。
exe 资源已通过 PE 解析验证：`.rsrc` 含 RT_ICON × 7 + RT_GROUP_ICON × 1，资源树完整。

### 3. 删除（移入回收站）

行尾悬浮操作和右键菜单各加一个「删除」，走 `SHFileOperationW(FO_DELETE | FOF_ALLOWUNDO |
FOF_NOCONFIRMATION | FOF_NOERRORUI)`——系统回收站语义，误删可还原，一次调用可批量。
不弹确认框（回收站即兜底）。

删除成功后条目立即打 `FLAG_EXCLUDED` 从结果里消失（搜索本来就会过滤该标记），
重建索引后自然对齐真实磁盘状态；失败（文件被占用等）给出明确 Toast。

悬浮按钮从 4 个变 5 个，浮层背景宽度同步 `4×24+6 → 5×24+6`——第一版忘改，垃圾桶被裁掉一半，
无头截图当场抓到。
